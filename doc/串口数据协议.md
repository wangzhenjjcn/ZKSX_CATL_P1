# USB 串口数据协议

本文给主机程序（PC / 工控机 / 其它进程）对接用。设备是 XIAO ESP32-S3，通过 **USB CDC 虚拟串口** 单向上报三路数据：压力传感器帧、麦克风 PCM、触点开关。当前固件 **没有下行命令**，主机只需打开串口并按本文解包。

参考实现：`tools/usb_mux_dump.py`。

## 1. 连接

| 项 | 说明 |
| --- | --- |
| 接口 | USB-C，枚举为 CDC 串口（Windows 为 `COMx`，Linux 多为 `/dev/ttyACM0`） |
| 波特率 | USB CDC **可忽略**。调用串口 API 时填 `115200` 即可 |
| 数据位 / 停止位 / 校验 | 8N1（对 USB CDC 同样无实际意义） |
| 流控 | 无 |
| 方向 | 设备 → 主机，二进制流 |
| 独占 | 同一时刻只能有一个程序打开该口。不要同时开串口监视器 |

板子复位后 COM 口可能先消失再出现，主机应自动重连。

## 2. 复用包格式

传感器、音频、开关走同一条字节流，必须按包解析，不能当纯文本或裸传感器帧读。

```
偏移    长度    字段        说明
0       2       magic       固定 `A5 5A`
2       1       type        见第 3 节
3       2       length      载荷字节数，小端 uint16
5       N       payload     N = length
5+N     2       crc16       CRC-16，小端
```

包总长 = `7 + length`。当前最大载荷 1920，因此单包最大 **1927** 字节。

多字节整数一律 **小端**。未知 `type` 应跳过（仍要按 `length` 把整包吃完），以便以后扩展。

### 2.1 失步恢复

1. 在缓冲里找 `A5 5A`。
2. 至少再读 3 字节，取出 `type` 和 `length`。
3. 若 `length > 2048`，丢掉这 2 字节魔数，从下一字节重新找头。
4. 收齐 `7 + length` 后算 CRC；失败则丢掉这 2 字节魔数再搜。
5. CRC 通过则按 `type` 分发 `payload`。

### 2.2 CRC-16

- 名称：CRC-16-CCITT-FALSE
- 多项式：`0x1021`
- 初值：`0xFFFF`
- 异或输出：`0x0000`
- 覆盖范围：**type + length + payload**（不含 magic，不含 CRC 本身）

```c
uint16_t crc16_ccitt(const uint8_t *data, size_t len) {
    uint16_t crc = 0xFFFF;
    for (size_t i = 0; i < len; ++i) {
        crc ^= (uint16_t)data[i] << 8;
        for (int b = 0; b < 8; ++b) {
            if (crc & 0x8000) crc = (uint16_t)((crc << 1) ^ 0x1021);
            else              crc = (uint16_t)(crc << 1);
        }
    }
    return crc;
}
```

```python
def crc16_ccitt(data: bytes, init: int = 0xFFFF) -> int:
    crc = init
    for byte in data:
        crc ^= byte << 8
        for _ in range(8):
            if crc & 0x8000:
                crc = ((crc << 1) ^ 0x1021) & 0xFFFF
            else:
                crc = (crc << 1) & 0xFFFF
    return crc
```

**样例（开关断开）：**

```
A5 5A 03 01 00 00 2C 28
```

- `type=0x03`，`length=1`，`payload=0x00`
- CRC 计算输入：`03 01 00 00` → `0x282C` → 线上为 `2C 28`

## 3. 类型一览

| type | 名称 | 载荷长度 | 典型频率 | 说明 |
| --- | --- | --- | --- | --- |
| `0x01` | SENSOR | 70 | 约 20 Hz | 压力传感器原始帧，校验通过后才发 |
| `0x02` | AUDIO | 1920 | 50 Hz（每块 20 ms） | 48 kHz / 16-bit / 单声道 PCM |
| `0x03` | SWITCH | 1 | 变化立即发，另每 200 ms 心跳 | 两路触点开关 |
| `0x04` | STATUS | 16 | 约 1 Hz | 调试计数，可忽略 |

USB 写不动时固件 **先丢音频**，尽量保住传感器和开关。因此 `0x02` 可能缺块，`0x01` / `0x03` 优先。

---

### 3.1 `0x01` SENSOR — 压力传感器

载荷就是采集器的 **70 字节原始帧**，MCU 不解析坐标，只做搜头和校验。

传感器侧 UART：460800、8N1、20 FPS。只有校验通过的帧才会打成 `0x01` 发出。

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | HEAD0 | 固定 `0xFF` |
| 1 | 1 | HEAD1 | 固定 `0x84` |
| 2 | 1 | CNT_H | 帧计数高 8 位 |
| 3 | 1 | CNT_L | 帧计数低 8 位。每帧 +1，16 位回绕 |
| 4 | 64 | 坐标 | 32 点 × 2 字节，顺序 `X0Y0 … X7Y3`（8 列 × 4 行） |
| 68 | 1 | Checksum_H | 校验和高 8 位 |
| 69 | 1 | Checksum_L | 校验和低 8 位 |

**计数：** `cnt = (CNT_H << 8) | CNT_L`。主机可用它检测丢帧。

**单点 ADC（11 bit）：**

```
value = ((Xh & 0x07) << 8) | Xl
```

`Xh` 仅低 3 位有效。点 `i`（0…31）对应：

```
Xh = payload[4 + 2*i]
Xl = payload[4 + 2*i + 1]
列 x = i % 8
行 y = i / 8
```

**传感器校验（主机可再验一次）：**

```
sum16 = (CNT_H + CNT_L + 64 字节坐标) 的低 16 位
Checksum_H = (sum16 >> 8) & 0xFF
Checksum_L = sum16 & 0xFF
```

不含帧头 `FF 84`，不含校验两字节本身。

---

### 3.2 `0x02` AUDIO — 麦克风

| 项 | 值 |
| --- | --- |
| 采样率 | 48000 Hz |
| 位宽 | 16-bit 有符号，小端 `int16` |
| 声道 | 单声道 |
| 每包采样数 | 960 |
| 每包时长 | 20 ms |
| 每包字节 | 1920 |

拼接各包 `payload` 即可得到连续 PCM。若中间缺包，时间轴会缩短，不要按包数硬对齐传感器 20 FPS（传感器仍约 20 Hz，音频按采样率播放）。

写成 WAV：1 声道、2 字节/样、48000 Hz。

---

### 3.3 `0x03` SWITCH — 触点开关

载荷 1 字节：

| bit | 含义 | 1 | 0 |
| --- | --- | --- | --- |
| 0 | SW1（板子 D3 / GPIO4） | 闭合 | 断开 |
| 1 | SW2（板子 D4 / GPIO5） | 闭合 | 断开 |
| 2–7 | 保留 | 必须当 0 处理 | |

硬件：开关一端接 GPIO，一端接 GND，内部上拉。未接线时两路恒为断开（`0x00`）。

发送时机：

- 去抖约 25 ms 后，状态变化立即发一包
- 无论是否变化，每 **200 ms** 再发当前值（心跳，用来判断链路还活着）

---

### 3.4 `0x04` STATUS — 运行计数

4 个 `uint32` 小端，共 16 字节。联调用，业务程序可丢弃。

| 偏移 | 字段 | 含义 |
| --- | --- | --- |
| 0 | sensor_ok | 校验通过并入队的传感器帧数 |
| 4 | sensor_checksum_fail | 搜到头但校验失败次数 |
| 8 | audio_dropped | 音频块因队列满或 USB 写失败而丢弃的次数 |
| 12 | usb_incomplete | USB 写出超时/中断次数 |

约 1 秒一包。

## 4. 主机侧建议

1. 打开串口后用较大读缓冲（例如每次 4 KB），按第 2.1 节组包。
2. 三条业务回调分开：`on_sensor(70 bytes)`、`on_audio(1920 bytes PCM)`、`on_switch(bits)`。
3. 传感器：检查 `FF 84` 和校验，再解 32 点；用 `cnt` 看是否连续。
4. 音频：按 48 kHz 播放或写文件；允许丢块。
5. 开关：以最新一包为准；若超过约 600 ms 没有 `0x03`，可视为 USB 掉线。
6. 不要假设包与包之间有空闲间隔，它们是紧挨着的。

带宽粗算：音频约 96 KB/s，传感器约 1.4 KB/s，开关可忽略。普通 USB CDC 足够。

## 5. 最小解包伪代码

```python
MAGIC = b"\xA5\x5A"
buf = bytearray()

def feed(chunk: bytes):
    buf.extend(chunk)
    while True:
        i = buf.find(MAGIC)
        if i < 0:
            buf.clear() if not (buf and buf[-1] == 0xA5) else buf[:] = buf[-1:]
            return
        if i:
            del buf[:i]
        if len(buf) < 5:
            return
        typ = buf[2]
        n = buf[3] | (buf[4] << 8)
        total = 7 + n
        if n > 2048:
            del buf[:2]
            continue
        if len(buf) < total:
            return
        pkt = bytes(buf[:total])
        del buf[:total]
        if crc16_ccitt(pkt[2:5 + n]) != (pkt[5 + n] | (pkt[6 + n] << 8)):
            continue
        dispatch(typ, pkt[5:5 + n])
```
